# Aegis Shield query bot + active mode (`aegis/bot.py`, `aegis/active.py`)

Files: `bot.py` (Python loop), `active.py` (invader watch, grading, state), `listener2.lua` (in-game inbox hook, `AE_IN.take()`), `reply.lua` (`AE_REPLY(key, kind, ...[, sid])`, `AE_REPLY_ERRS()`), `fastmap.lua`/`fastmap.py` (whole-map snapshot `AE_MAP`, `ladder(n)`), `invites.py` (manual invite approval). Bump the `ver`/`AE_REPLY_V` constant in a Lua file whenever it changes, or the idempotent installer keeps the old version in game memory.

## Grammar (after `@aegis` / `@aegis shield` in groups; DMs need no tag)
Check forms in this order; keyword forms first so player names never collide:
| Message | Meaning |
|---|---|
| `player <name>` / `player [TAG] <name>` / `alliance <tag>` / `alliance [tag]` | explicit search (brackets stripped) |
| `invaders` / `invaders 264` (`K264`, `#264`, `kingdom 264`, `from 264`) | every city whose `playerSid` is not home / only that kingdom |
| `status` / `ping` | 'Online. N searches running. Active mode ON/off.' (jumps the text queue; kept working but NOT advertised: an offline bot cannot answer it) |
| `commands` / `command` / `help` / `?` | the everyday help list (see below) |
| `covert` / `coverts` / `covert ops` [+ `264`, `K264`, `#264`, `kingdom 264`] | covert-op scan, allowlisted DMs + listed groups only (see Covert ops); anyone else gets the normal unknown-command reply |
| `active on` / `active off` | only ids in `config/active_allow.json` (re-read per message), from the alert room or by DM (DM gets 'Active mode ON/OFF. Alerts go to <alert room>.'); anyone else gets the normal unknown reply |
| `join` (exact word, any case) | invite the sender to the `config/join.json` group (see Join command); DMs, or groups when tagged |
| `exclude [TAG]`, `include [TAG]`, `excludes` | anyone in the alert room |
| `kingdom <n>` | card at that kingdom's royal city (500,500), titled 'K<n> Royal City'; `kingdom -2`, `kingdom 2.5`, bare `kingdom` -> 'Use kingdom <1-max>' |
| `[kingdom ]<n> x,y` / `K<n> x y` / `n:x:y` / `x,y` | card at that spot, titled 'K<n> x,y' (default kingdom = home) |
| `[TAG]` / `[TAG] name` | alliance search / player within that tag |
| anything else (<=40 chars) | bare player name; if it matches nobody: 'No player by that name on the map. Send commands for the list.' Unparseable input: 'Unknown command. Send commands for the list. In groups, start with @aegis.' |
- Help text = the owner own wording, one line per command, everyday commands only (player, alliance, invaders [+kingdom filter], kingdom), the wildcard line ('Wildcards work in names: * = any letters, ? = one letter (e.g. @aegis jen* or @aegis *fox)') right after the player line, plus 'Want to search privately, DM me. In DMs, @aegis is not required.' Never list admin commands, the test group, or `status`. Each line is its own message, split only where a line exceeds 100 characters (chat bubbles do not render line breaks or formatting reliably).
- Player searches matching more than 10 cities: reply 'Found N players matching. Sharing the 10 strongest. Use more of the name to narrow it.' and share only those 10 (wildcards like `a*` match hundreds).
- Bare numbers or short `k9`-style words are player names, never kingdoms: require the explicit `kingdom` keyword wherever a name could look like a number.
- `*` and `?` wildcards. `alliance` searches other servers only; a home-kingdom tag gets 'Home kingdom alliances are not searchable'.
- Validate kingdoms with `Data.ServerInfosData:ExistServerId(n)` / `:GetMaxServerId()` (loaded at login). Reply 'Kingdom N does not exist (max M)' instead of making a card.
- Card labels are built from map data or the numbers, never from the sender's text. All reply texts are fixed templates, max 100 characters (the server does not enforce the chat-box limit, so over-long bot texts look non-human); `reply()` truncates as a backstop.
- Plain-text coordinates in chat are not tappable; only one point per card (`messageType=19`).
- Group commands need the `@aegis` tag even in the bot's own test group; untagged text is ignored by design.
- Before restarting after a grammar change, run a table of sample messages through `B.parse(...)` offline and show the results.

## Concurrency and chat limits
- The map snapshot is not the bottleneck (one refresh ~4-5 s answers every query). Start every query immediately from the current snapshot (refresh if older than ~20 s), send its 'Found N' text, then send cards ROUND-ROBIN across active queries so a one-player lookup is not stuck behind a long invader list.
- ErrorCode 21304 = 'Same input too frequent' (identical message in the same room); 21302 = 'Input too frequent' (speed). Suppress duplicates yourself: a card already sent to that room in the last 120 s gets 'Same result as shared above.' instead (in-memory `recent`, keyed by room ser + x,y,label). Active-mode cards bypass this (`nodup`).
- The speed limit is per ACCOUNT: distinct cards 0.5 s apart were refused about 6 in 10 whether they went to one room or alternated between two, and 8 in 12 across three rooms at 0.33 s. Per-room pacing does not help. Rate tests use `aegis/ratetest2.py` (distinct cards, the owner DM + test groups only, bot and watchdog stopped, results to `logs/actions.log`); never rate-test with identical cards.
- One outbox for ALL outgoing messages, including live covert hits sent mid-scan (they must wait for `next_send` and set it, or a burst of hits draws 21302). Adaptive pace: start 1.5 s, double on any refusal (cap 10 s), ease back /1.5 after 5 clean sends. Errors that arrive before the next send belong to the previous one: put it back at the head and retry (max 5).
- Before each card re-read the player's row from the snapshot; skip players who left.
- Chat mute (21307 'Doctor is muted'): text is refused, share cards still go. On 21307 for a text, set `muted_until = now + MUTE_PAUSE` (30 min) and re-send that text as a card; until then every text (replies, notices, digests, covert summaries, dup notices) goes out as a point-share card on the home royal city (500,500) with the text as its label, cut at 110 chars (`Bot.as_card`, the owner OK; labels render in full). After the pause, text is tried again.
- Outbox priority: people's replies and search-result cards go before shield alert items (key `'active'`); alerts only go when nothing else waits, so commands stay fast during a wave.
- `reply()` logs every non-'sent' result from `AE_REPLY` (`reply <kind> not sent: ...`): when a user says nothing arrived, read those lines and `AE_REPLY_ERRS` before guessing.
- Limits (a KvK rush has hundreds of invaders and many askers): 2 active queries per sender, 10 overall; `invaders` shares only the 20 strongest ('Found N invaders. Sharing the 20 strongest. Use invaders <kingdom> for one kingdom.'); other searches 50; the same search already running in the same room merges ('Already sharing that here, see above.'); a new multi-card search while more than 100 cards wait is turned away with an estimate ('Busy: about N min of results queued...'); jobs with 3 or fewer cards left go before the long lists.
- The loop must never block on a job: read the inbox every iteration (0.1 s while busy, 1 s idle).
- Load test offline before changing queueing: `aegis/stress_test.py [invaders]` replaces every game call (fake map, `room_of`, `reply` recorder, `server_errors`) and the clock (`B.time = A.time = Clock()`), fires a scripted crowd of requests across rooms with active mode on, and prints per-request wait to first reply/first card, cards per room and the minimum gap between sends. The waits it shows (~35 s first card in a 5-list rush at 1.5 s) are the floor the per-account limit allows.

## Active mode (invader watch)
- Alert room: `config/active_room.json` `{"room": "<group name>"}` (currently the group Aegis owns, Aegis Defender; default Aegis Test). Alerts go via a synthetic reply key `AE_IN.rooms['active']` set by name lookup each cycle. After moving the room, bump `RECARD` in bot.py: the whole map is re-carded once so the new room starts complete.
- Schedule `AUTO=True`: on for the whole server Saturday (server = UTC-2, so 15:00 Sat to 15:00 Sun NZDT). A manual `active on/off` is stored with `override_day` (server date) and only lasts until the next server midnight, then the schedule takes over again (`is_on`: override if `override_day == server_day()`, else `AUTO and scheduled_on()`). Test the schedule offline over a simulated weekend (`is_on(state, now)` at the edges) before deploying. `deploy_phone.py` never ships `config/active.json` (the phone's live state).
- Announce switches with a short themed line ('AEGIS SHIELD ACTIVATING. Invader watch online.' / 'AEGIS SHIELD STANDING DOWN. Invader watch offline.'). Persist `was_on` in the state so a restart neither re-announces nor misses an off switch.
- Every 30 s: full snapshot diff of foreign cities. EVERY invader gets a card (user wants all shared). Re-alert only on move > 20 tiles or shield dropped; keep `seen {id:[x,y,shield]}`, drop ids no longer on the map. Max 20 alerts per cycle (= the 1.5 s pace over a 30 s cycle; a 34-card burst drew no 21302/21304). Coordinates are what users value: every alert is a card, never a count-only line.
- First look after each activation: mark everyone already present as seen and post ONE summary line ('Watching N invaders already here: ... Send @aegis invaders for their cards.') instead of a card flood. Gate it on a `baselined` flag set by the baseline and cleared by `active on`/off, never on 'seen is empty' (an empty map after KvK keeps that true and re-posts every cycle).
- Card title reads as a sentence, no 'NEW' prefix: `[TAG] Name - K266, Lv28, 87M power, no shield, 2 reinforcing. Grade SR`; prefixes only for 'Moved:' / 'Shield down:'. No advice texts ('Grade UR: only X should try' was dropped by the owner: the card's grade is enough).
- Grades = rank of invader power on the home power ladder from the same snapshot (`AE_MAP.ladder(200)`), named in game rarity tiers: MR above everyone (rally only), UR top 3 (name them), SSR top 10, SR top 50, R top 200, N below. `garrisonNum>0` counts as 5 ranks harder.
- State `config/active.json` (week, exclude tags, seen, override) is wiped each server week (exclusions are per KvK). The running bot rewrites it every cycle: change it only via chat commands or with the bot stopped.
- Shield is only as fresh as the 30 s cycle; brief toggles are missed, no expiry time is in the map data.

## Summary mode (`active.mode()`, OFF: `SUMMARY_MODE = False`)
the owner switched it off: count-only update lines carry no coordinates, and the surge rule fires at every reset (everyone ports in within minutes: ~37 in 5 min), hiding the wave. `mode()` still runs for the KvK winner watch ('KvK result: royal city now held by ...'). If it is ever re-enabled: cards for MR/UR/SSR (`CALM_GRADES`), first digest posted immediately (`dg_at = 0`), then every 10 min. Triggers kept in code:
- KvK fight window: no fixed weekday any more. `Bot.fight_window()` (cached 5 min) returns (throne shield_end, throne fight_end) from `FM.throne()` ONLY while the Kingdom War activity exists on the account (`KW_PRESENT` Lua: an Activities entry with `zoneContestDetail`); no Kingdom War, a failed lookup or odd throne times = no window, normal alerts. It is passed to `A.mode(..., window=)`: window runs from 1 h before the start to the fight end; ends 30 min after the KvK holder changes (`FM.kingdom_holder()` holder tag/sid/victoryTimeMs differ from the value at window start, announced 'KvK result: royal city now held by ...'). Holder data may not refresh live and a holder who wins again changes nothing. The lookup only runs while active mode is on, so check its log line ('active: fight window none (no Kingdom War)' / 'set from the throne timers') only after the Saturday switch-on. Test `mode()` offline with fake times (no window, before/inside/after, holder change, +30 min).
- Arrival surge: 10+ new (unseen, not excluded) invaders in 10 min, ends 20 min after it calms. Count arrivals BEFORE deciding the mode (`count_arrivals`), or the first wave goes out as cards.
- Hourly cap: 40 alert messages in the last hour.
Test mode logic offline: fake `FM.query`/`ladder`/`kingdom_holder`, stub `A.save`, run `active_tick()` cycles and print the queued texts.

## Covert ops command (`aegis/covert.py`)
- Allowlist `config/covert_allow.json` (name -> player id from `sourceMessage.senderId` on their messages) for DMs, plus `config/covert_rooms.json` (group names whose every member may use it, tagged as usual; `[]` = none); both re-read on every request, so edits need no restart. Group match: `in_group(key, names)` compares the message's roomInfo (`G.ser`) with each named group room's `m_Dto.roomInfo`. Replies go back to the room the request came from.
- Flow: start notice ('Covert scan of K<n> started, about 2 minutes. Collectable top ops are shared as they turn up.'), top-tier ops shared live during the scan, then a summary under 100 chars ('K263 covert: N found, M ready. Best 5 below.', '+ N top ops still running, first ready in X min.', next-ready time if none, 'Plunder limit reached.'), then up to 5 cards for the best ready ops not already shared live (most boxes, then antitoxin, then free slots).
- The scan blocks the loop, so its sends (start notice, live hits) bypass the outbox: `Bot.send_now()` waits for `next_send`, settles the previous send's errors, checks AE_REPLY returned 'sent' and AE_REPLY_ERRS, backs off and retries once on 21302, and logs each attempt. Unpaced, unchecked sends right before a burst of hits get refused silently.
- Cards are the game's OWN covert-op card (players find them clear: it shows stars, rewards and owner itself): `AE_REPLY(key,'secret',x,y,uniqueId,taskId,sid,'[TAG]Owner')` builds messageType 19 `shareMessageDto.secretTask{x,y,uniqueId,content}` with content `{"playerName":"[TAG]Name","secretTaskId":id,"shareType":6,"sid":k,"x":..,"y":..}` (copied from real covert shares in kingdom chat); guard permit `secret_share` (exactly one card kind per message, shareType 6, exact room).
- After a scan of another kingdom the map view must be back on home: `covert.go_home()` retries 3x and raises if stuck, and `Bot.refresh()` calls it whenever fastmap reports the wrong server id.
- Top tier = secret level 5 with 15 plunder boxes (one task id, found from `Config.SecretTask` at scan start, never hard-coded): its card goes out the moment it appears in a reply, ONLY if collectable (completeTime passed, a free plunder slot, not ours). The native card shows no timer, so a running op looks like 'can't collect' to players; still-running top ops go into the summary text instead. Every op on the map has an occupier, and type 9916/9917 does not mean started, so 'ready' is decided by completeTime alone. An op can be re-occupied mid-sweep (same uniqId, new timer): keep the NEWEST copy of each op, not the first. `aegis/covert_probe.py` prints a status breakdown of one scan (stop watchdog + bot first).
- A zoom-3 sweep started from the city view (`view()` == ('0', home)) never finishes: always go through `covert.scan()`, which enters the world map first.
- 0 ops on a reachable kingdom is impossible (~1,500 normally): the game session has stopped delivering `secretTaskInfo` points to the sweep hook while players still arrive. The bot replies 'came back empty (game glitch)... send covert again in about 3 minutes', logs it and drops `aegis-ctl/restart_game`; a fresh session scans normally. Debug order if it recurs: sample one fresh zoom-3 block with a histogram hook of point types (`tostring(p.type)` + whether `secretTaskInfo` is set) to prove the ops exist, then run the sweep's HOOK+CHAIN on 4 blocks and read `#LPA_KS.rows` / `#LPA_KS.sec`.
- The bot loop blocks for the whole scan (~80 s home, more for another kingdom): write `bot_busy.txt` non-zero first, reset `map_at` after (the map view moved). Other queries are answered afterwards from the listener queue.
- Before testing a scan standalone, stop the bot (one driver) and check no the owner tool (`invader_watch`, `lpa_sync`, `covert_ops`, `kingdom_sweep`) is running.
- Speed: the sweep now keeps 2 map requests in flight (`FAST` in covert.py, falls back to the old sequential pace on any missed block or ErrorCode): a whole `covert` takes ~43 s instead of ~2 min. The server answers about one block per second whatever the overlap, so that is the floor for one account. Measurements, the rejected ideas (result cache = stale data the owner distrusts, parallel accounts) and the offline search for a lighter request: `references/covert-speed.md`. The bot loop is still blocked for the scan (invader watch cannot refresh, map view leaves home).

- Why PC-side: the service key stays on the PC (the phone could do HTTPS fine, but would need the key); the task has StartWhenAvailable, so a PC that was off runs it on wake.
- Bridge: `lpa_run.run` is replaced with `R.run(code, allow_send=True)` before importing lpa_sync / covert_ops / kingdom_sweep, and each module's imported `run`/`lua` name is patched too. Never roster/duel/elixir (own-alliance reads), no covert (the owner).
- A finished run logs 'saved N players, M changes'; 'REFUSING to save' = the tool's own completeness guard (thin blocks), check `kingdom_sweep_*_refused.json`.
- Scheduling on Windows: write the `.bat` with the file tool (bash `printf` mangles backslashes), register with PowerShell `Register-ScheduledTask` (`New-ScheduledTaskTrigger -Daily -At 15:00`, settings `-StartWhenAvailable -ExecutionTimeLimit 30min`); `schtasks /tr` quoting of paths with spaces fails from bash.

## Running it
- One instance only (PC or phone, never both). Phone-hosted: restart via `python aegis/deploy_phone.py` (new code) or an empty `/sdcard/Download/aegis-ctl/restart_bot`; read `/sdcard/Download/aegis-logs/bot.log`. PC-hosted: `aegis/restart_bot.ps1` (stops any `aegis.bot\.py` python, archives `bot_out.log`/`bot_err.log`, starts detached via Start-Process so it survives the agent session). Confirm `bot started` in `bot.log` and an empty `bot_err.log`.
- Treat 21304 on a card as 'already in that room' (e.g. sent before a restart, when the in-memory `recent` is empty): skip it with no slowdown; back off only on other refusals.
- `install()` checks each Lua file returned OK and that `AE_IN`, `AE_REPLY`, `AE_MAP` exist afterwards (raises 'install incomplete' otherwise); the loop reinstalls every 60 s and immediately after any error naming those globals or the guard, so a game restart costs about a minute. A silent partial install (game still loading) otherwise leaves the bot erroring on `AE_IN` forever.
- Map refresh needs `Data.WorldData.serverId == home`. Right after entering the world map the first refresh can read serverId nil or time out: `Bot.refresh()` calls `go_home()` and retries up to 3 times. Repeated 'no full map reply in 20 s' with no ErrorCode = the game lost its connection; the watchdog presses the reconnect dialog. Map refresh takes ~4 s on the emulator, ~7 s on the S10.

## Invites and one-off posts
- Never auto-accept. `invites.py` lists invite cards from DM rooms; `accept "Exact Name"` (the room's name as listed, often a number; the group may show a different name once joined) opens a one-shot `ChatGroupConfirmC2S` permit and sends `{agree=true, groupRoomInfo=inv.chatRoomDto, messageId=<invite msg id>, roomInfo=<DM roomInfo>}`. Only after the user says yes.
- A user-approved text post: show the exact text first, send with a `msg='text'` permit tied to that text + room, log to `logs/actions.log`.

## Join command (sending invites)
- `join` -> `Bot.join()` -> `AE_INVITE(group, playerId)` (reply.lua) -> `chat.ChatGroupInviteC2S{roomInfo = room:GetChatRoomDto(), memberId = {playerId}}`; guard permit `msg='ChatGroupInviteC2S', group, member` passes only a one-element memberId list with exactly that id to exactly that group. `memberId` is a repeated field: a scalar fails encode silently and nothing is sent.
- the owner spec: send the invite every time it is asked, DMs or tagged groups; NO member tracking (the game ignores invites to existing members). Gates kept: home-kingdom senders only (`home_only` in `config/join.json`, home kingdom from `senderInfo.serverId` on the sender's chat messages via `AE_SENDER_SID`; the map fails on KvK day because home players are away), 30 s per-player gap against double sends, 60 invites/h, all in memory.
- The server sends no ack for an invite: confirm with the user that it arrived in their chats.

## Uptime: watchdog (`aegis/watchdog.py`)
- Start/restart with `powershell.exe -NoProfile -File aegis/start_watchdog.ps1` (stops an old one, starts detached). `python aegis/watchdog.py --once` runs one pass for tests. Branch order, dialog table, phone checks, reader rebuild: `references/devices-and-recovery.md`.
- The bot heartbeat stays fresh while the game is disconnected, on a dialog, or has lost its reader (the bot keeps looping on timeouts), so the dialog probe and reader-silence tracking are what catch those, not the heartbeat.
- Never restarts the game while the owner tools run (`invader_watch`, `lpa_sync`, `covert_ops.py`, `kingdom_sweep.py`). Caps per hour: 3 game, 6 bot, 12 presses, 2 reader rebuilds; 4 reconnect presses within 10 min = restart the game instead (`PRESS_LOOP`).
- Test each branch offline: stub `sh`/`adb`/`pythons`/`R._raw`, fake the heartbeat file and `time.time`, step `tick()` and print the calls; for the live reconnect press, cut the connection with `Network.DisConnect()` (own client, logged in `logs/actions.log`).
- Not covered: PC reboot (offer a Task Scheduler logon task running `start_watchdog.ps1`, only with the owner yes: it changes his PC) and unknown pop-ups after a game restart.
