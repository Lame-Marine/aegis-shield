# Game internals and probing (no player data here)

## Probing an unknown function from Lua (read-only)
- List send functions: iterate `package.loaded`, keep names containing `Proto.Send`, list their function keys (filter by keyword).
- What a function calls: `debug.getinfo(f,'S')` (source file + line), `debug.getupvalue(f,n)` (captured tables), `string.dump(f)` then scan printable constants (shows globals like `Network` and the message name).
- Find a message type by name: `for name, basename in require('pb').types() do ... end` (filter `basename`), then `pb.fields(name)` for its fields; this lists every server message (e.g. all `MessageDto` detail kinds) without any source code.
- Parameter and upvalue NAMES survive in the compiled scripts: `debug.getinfo(f,'Su')` (`nparams`, `nups`, line range), `debug.getlocal(f, i)` for i <= nparams, `debug.getupvalue(f, i)`. Enough to tell what a callback expects (e.g. `SelectedTextureImage(texture)`) before calling anything.
- Constants and enums: scan `package.loaded` modules whose name contains the topic (e.g. `Chat`) two levels deep for number fields / function names matching keywords (`Pic`, `Image`, `Share`).
- What it sends at runtime: temporarily wrap a global with a log-only pass-through that records the first N calls, read the log, then restore the original in the next command. Always restore.
- Find WHICH game function does something (source is compiled): walk `package.loaded` two levels deep (plus each table's metatable `__index`), `string.dump` every function and search the bytes for needle strings (message names, field names such as `chatPicDto`, `SendChatPicC2S`); ~25k functions fit in one 90 s reader call. Print `module.path [needles] file:line` per hit. This found the chat picture sender (`ChatRoom:SendChatTexture`) in one pass after field-name guessing failed. It only sees modules already loaded: UI panels load when first opened, so a request with no caller found (e.g. `ChatGroupInviteC2S`) is called from an unopened panel; decode the script bundles offline instead (see Chat rooms: reading lazily loaded UI scripts).

## Network layer
- Requests: `Network.Send(name, data)`; modules `require('Logic.Proto.Send.<module>').<Name>C2S(table)` call it. Heartbeat is `'Pong'`.
- Responses: `MessageReceive.<Name>S2C(data)` handlers.
- Refusals do NOT come back on the S2C handler: they arrive on `MessageReceive.ErrorCode(d)` with `d.name` (the request) and `d.code`. To see why a send failed, hook `ErrorCode` (pass-through, restore after). The game's own text for a code: `GetTranslation(tostring(code))` (e.g. '21307' -> 'Doctor is muted'); `GetTranslation('ErrorCode_<n>')` also works for some codes.
- Error codes seen: 10004 insufficient resources, 10003 insufficient items, 20200 requirements not met, 20203 no idle queue, 20205 building level mismatch, 20211 BuildingCompleteC2S refused (building not collectable that way), 20308 PlayerQueueFreeC2S refused, 80002 relocate target invalid (out-of-range tile), 1001 relocate into another kingdom refused (no S2C reply), 1023/300007 wrong parameter (also: zoom-3 map view larger than ~150x200), 30253 not in an alliance, 21106 rename refused (likely name taken; no charge), 21302 'Input too frequent' (chat speed limit, per ACCOUNT: two or three rooms alternating at 0.33-0.5 s are refused as often as one room), 21304 'Same input too frequent' (identical message repeated in the same room), 21307 'Doctor is muted' (chat mute: text refused, share cards accepted; no mute timer on the client), 1000 world view of another kingdom without entering its map, -20001/-20005 connection drop (reconnect dialog), -10013 and login 1019 = account logged in on another device (the watchdog takes it back after 60 s), 1021 logged out due to inactivity (restart the game), 1004 server under maintenance, 40005 event has ended / not available to this account.

## Wire protocol (packet capture of our own connection)
- Find the game's connections: `pidof com.phs.global` -> `stat -c %u /proc/<pid>` (uid) -> rows of `/proc/net/tcp*` with that uid and state 01. One TCP connection to the game server on port 9929 (an AWS Global Accelerator address); the rest is HTTPS 443.
- Capture (rooted instance, inside its VPN): `su -c 'tcpdump -i tun0 -s 0 -w /sdcard/x.pcap tcp port 9929'` for ~40 s while triggering a known request (a fastmap refresh); pull, analyse, delete. Link type is raw IP (101).
- No TLS. Frame: `70 a3 | u16 x | u16 name_len | name (ASCII message name, same as pb names) | u32 body_len | body`; every byte of a capture parses this way. `x` looks random per frame; its role is unknown.
- Body = `pb.encode(name, table)` scrambled per byte: `cipher = ((plain + a) & 255) ^ b`; per direction, frame k (counting from 0 on a fresh connection, empty-body frames included) uses `a = (126 - k) & 255`, `b = (144 + 16k) & 255` (the pair (254, 16) is the same mapping). The start values are FIXED and identical for both directions (found from a fresh-login capture, where exactly one pair makes all 8 login frames valid protobuf), so any captured stream decodes without known plaintext. `x` is still unexplained (random-looking, not a body checksum). Login order, `LoginReqC2S` fields (a 344-char SDK token in field 20, resource version, device ids) and the `DisconnectCode` 1003 a fresh guest gets: `docs/protocol.md`; capture + dummy-device recipe: `references/dummy-research-device.md`.
- Method that found it: encode a request you just sent with the game's own `pb.encode` (known plaintext; same length as the captured body), check the substitution is consistent per byte value, brute-force the 65,536 `(a, b)` pairs per formula; for server frames keep the pair whose output is valid protobuf for that message's fields (`pb.fields`), then read the step between consecutive frames. Scripts: `aegis/pcap_peek.py` (framing, `--frames`), `aegis/scramble_fit.py`. Notes: `docs/protocol.md`.

## Message schemas (read the server contract before any send test)
- `require('pb').fields('<Name>C2S')` iterates `name, number, type` of the protobuf message: the exact fields the server accepts. Use it before guessing payloads.
- Building: `building.UpgradeBuildingC2S{uuid, level}` where `level` is the building's CURRENT level (server compares with its own record: mismatch = 20205, so no level skip or rollback through it; the GM-only auto-tutorial is the only fast path and players cannot reach it); `BuildingCompleteC2S{uuid, level}`; `BuildingDemolishC2S{uuid, free, useDiamond}`; `CreateBuildingC2S{buildingId, x, y, useDiamond}`. Queue: `queue.PlayerQueueFreeC2S{uuid}`, `PlayerQueueSpeedupC2S{uuid, itemId, itemCount}`, `PlayerQueueCompleteC2S{uuid}` (gem path), `PlayerBuildingSecondQueueC2S{itemId}`.
- Teleport: `world.WorldCityRelocateC2S{relocateType, target={sid,x,y,pid}}`; `WorldDefines.RelocateType` HitFly=0, Random=1, High=2 (Direct Relocate item), Union=3, Born=4, ZoneContest=5, UnionContest=6, VOLCANO=7. Items `item_UseUp_targetMove` (Direct), `item_UseUp_unionMove` (Alliance), `item_UseUp_randomMove`. Client bounds `WorldMapHelper.IsValidTile`: 1-999 on both axes. Server also refuses out-of-range tiles (0,0 / 0,1000 / 35535 / 35520 -> `WorldCityRelocateS2C success=false` + 80002, nothing spent; the reply echoes the target as 35535,35535) and a type-2 relocate into another kingdom outside KvK (ErrorCode 1001, no S2C). Untested: the cross-kingdom relocate types (`WorldMapHelper.CrossRelocateActivityType` 110/112/120) and the same request during KvK. Test with `aegis/relocate_test.py X Y [SID]`.
- Server tests that change the account: state the request, the possible outcomes and the cost, get the user's go, stop the bot, then send ONE request per call with an `ErrorCode` + S2C hook and before/after state (level, state, resources, gems) - `aegis/build_test.py <uuid> <level>`. A refusal on a building whose normal upgrade is blocked is ambiguous: repeat on a building whose normal path passes (control). After two refused attempts at the same step, read the client's own handler instead of trying more payloads. A started upgrade on a low-level building may not finish via `BuildingCompleteC2S` or `PlayerQueueFreeC2S`; the collect path is still unknown, so do not leave buildings mid-upgrade casually.
- Server time: `require('Ability.Tools.Common.TimeUtil').GetLocalServerTimeZoneOffset()` = local minus server hours (K263 server = UTC-2).

## Static config tables (read-only identification)
- Find a table: `for k,v in pairs(Config)` and filter names by keyword (e.g. 'build'). Rows load lazily but `Config.<Table>[id]` and `pairs(Config.<Table>)` both work inside `pcall`; dump rows with a depth-limited recursive printer.
- Buildings: `Config.Building[id]` (`name`, `classifyName`, `info[]` with effect `translate`, `maxLv`, `lock_show_condition`). Per level: `Config.BuildingLevel[id*100+lv]` (`precondition = {{id=20103, param1=<buildingId>, param2=<level>}}` = 'that building at that level'); cost/time/reward: `Config.BuildingUpgrade[id*100+lv]` (cost type 1 food, 2 wood, 3 herbs/stone). Copy limits: `Config.BuildingCountLimit` rows `{buildingId, count, lockCastleLevel}`.
- Building 1001 = Sanctuary. Building 5047 = '2nd Workbench' (second Research Lab: research speed + free speedup time, max Lv30): every level requires Sanctuary 9999 and the menu hides it below Sanctuary 999, i.e. not reachable by levelling; the real unlock route (pack/privilege/event) and whether the server enforces 9999 are unknown.
- Identify an unknown id from config first; a server-side test of a client-only gate (e.g. sending a build request past an impossible precondition) is a ToS-grey exploit test: propose it to the user with the exact cost, do not run it unasked.

## World map and sharing
- Map state checks before any sweep: `Data.WorldData.serverId` keeps its last value on the city screen, so decide 'on the world map' from the active scene name (`WorldScene`), as `covert.view()` and `fastmap.refresh()` do. Entering the map from Lua (`WorldMapHelper.LocateToWorldMap(x,y,sid)`) can leave `serverId == 0`, and map requests then get no reply at all: go back to the city and out again (the user can do it by hand). Replies arrive via `MessageReceive.WorldMapViewS2C(data)`; the vendored sweep hooks `Data.WorldData.SetWorldMapView`, which only fires once serverId is right, so zero replies = wrong serverId or not on the map, not a broken hook. The first refresh right after entering can time out or read nil: retry (Bot.refresh tries 3 times).
- No server-side player search by name: finding a player means a map sweep (`world.WorldMapViewC2S{viewLevel=4,width,height,center={sid,x,y},openView=false}`; level 4 returns cities without monsters). Map is ~1000x1000, blocks 140x200, game-like pacing 0.45-0.95 s between replies.
- City rows: `worldPointInfos[i]` with `type==1`, `worldCityInfo{playerId,playerName,playerUnionShortName,playerPower,level,shielding,shieldType,playerSid,garrisonNum,killEnemyCount,defendReducedValue,state,...}`, `point{x,y}`. `playerSid ~= 263` = visitor from another kingdom. `garrisonNum` (0-5) is probably reinforcing marches (unconfirmed); `state` 1/2 with non-zero `defendReducedValue` look like burning/damaged walls.
- Delimited rows that carry player names: names can contain the delimiter (`|`), so parse fixed fields from both ends and join the middle as the name.
- Coordinate share (what the Share button sends): `require('Logic.Datas.Chat.ChatUtils').Share(4, 1, room:GetId(), {pointMessage={x=X,y=Y,content=json{name='[Tag] Name',shareType=1,sid,treasureId=0,x,y}}})` where `room` is the existing DM room from `Data.ChatData:GetRoomListByChannelType(4)` (match `room:GetName()`). It becomes `SendChatMessageC2S{roomInfo={parentChannel=4,childChannel=1,roomIdentId={PersonalCommonIdent={playerId=<recipient>,otherPlayerId=<me>}}},messageDetail={shareMessageDto={pointMessage=...}},messageType=19}`. `ChatUtils.ShareToPrivate(content,openChat,playerId)` passes content through unchanged, so give it the pointMessage form, not the flat panel params.
- Recipient player ids: senderInfo.playerId on their messages in the DM room (`m.m_Dto.senderInfo`).
- Whole kingdom in ONE request (~4-5 s, ~14.6k cities): the server only sends points that are new compared with this session's previous view, so first send a 2x2 'reset' view, then `{viewLevel=4,width=1000,height=1000,center={sid,x=500,y=500}}`. Faster than a block sweep; this is what `fastmap.lua` does.
- Map landmarks: royal city/throne at 500,500 (`type==10`, `worldThroneInfo`), four towers at 491/509 (`type==9`, `worldTowerInfo`, with kills per kingdom).
- The throne point's `worldThroneInfo.worldTempleBattleBuildingInfo` (occupiedUnionShortName/Name/Sid, shield, shieldEndTime, fightEndTime 8 h later, truceEndTime, state, isCross, march counts) is the inner-kingdom Royal City Scramble (Friday 12:00 server time) and its own king. It is in the zoom-4 1000x1000 reply, so fastmap captures it free (`FM.throne()`).
- The KvK result is elsewhere, in cached `Data.TempleData`: `T:GetKingdomOccupyInfo(sid)` = player holding that kingdom's royal city + `unionSimpleInfo{unionAlias, unionName, serverId}`; `T.kingdomInfos[sid]` has `victoryUnionSimpleInfo`, `kingPlayerName`, `kingUnionSimpleInfo`, `victoryTimeMs` (read 0 even after a win), `truceEndTime`/`fightEndTime` (= Scramble times). Loaded for home and recent opponents only. `FM.kingdom_holder()`. KvK fight: Saturday 12:00 server time, ~2 h.
- Find where a value lives by walking tables for it: recursive pairs() over `Data` with a depth/budget limit, matching e.g. the alliance tag the user sees in-game.
- Cards may point at ANY kingdom: put the target `sid` in the content JSON (tap-through to the other kingdom confirmed). The card `name` is free text the server never checks. Kingdom list: `Data.ServerInfosData` (`serverList`, `ExistServerId(n)`, `GetMaxServerId()`), loaded at login.
- Viewing another kingdom's map: a bare `WorldMapViewC2S` with `center.sid ~= home` gets ErrorCode 1000. The working path is the game's own 'enter that map' call, `GlobalMapCtrlManager:GetManager():EnterNormalMap(k, {x=500,y=500})`, then normal views with `sid=Data.WorldData.serverId`; wait until `Data.WorldData.serverId == k`, and always enter home again afterwards (`EnterNormalMap(Data.UserData.serverId, ...)`). Only kingdoms in `Data.EscortData.serverIds` (the caravan-robbing screen's list) are enterable; refresh it with `Data.EscortData.serverIds=nil Data.EscortData:ReqQueryCanBeRobbedEscortCartList()` and poll. Foreign views reply only via `MessageReceive.WorldMapViewS2C`.
- Zoom limits: zoom 4 accepts a 1000x1000 view (cities only). Zoom 1-3 views are capped at about 150 wide x 200 tall (140x220, 160x180, 200x200 all get 1023; it is a shape cap, not area), so a zoom-3 sweep needs 35 blocks of 150x200 (~80 s with game-like pacing).
- Covert ops = secret bases, point `type` 9916 (`Secret_Base`) / 9917 (`Secret_Base_3x3`) with `secretTaskInfo{uniqId, taskId, occupierId, occupierName, occupierUnionId, occupierUnionShortName, completeTime (ms), plunderedPlayerIds}`; they appear ONLY in zoom 1-3 replies. `Config.SecretTask[taskId]{secretLevel, quality, grabTimes (3), grabReward, reward}`; plunder boxes = 'Secret Reward' items (type 99) in `grabReward`. Top task: secret level 5 / quality 5 with 15 plunder boxes (152 for the owner); other Lv5 give 6. Own state: `Data.UserData.gameUid`, `Data.SecretData:ReachMaxPlunder()`. Ready = completeTime passed, fewer than 3 plunderers, not ours, not plundered by us.
- Chat sends: the server enforces neither the input box's length limit nor its character filter. Plain-text coordinates are not rendered as links.

## Game text and event mechanics (answering 'how does X work' questions)
- Order: player guides first (lastasylum.gg/en/events/..., wiki-last-asylum.com, last-asylum-wiki.vercel.app; they copy the in-game rules pages), then the client's own text, offline: pull `files/ABAsset/19/gamedata_language_f_en.assetbundles` with adb (no reader, no bot pause needed) and open it with UnityPy: 83 TextAssets, each plain CSV `KEY,English text` (one per module: Union, ZoneContest, ErrorCode, lang_abc = main, ...). Grep values for the feature name, then list every key sharing the found key's prefix: internal codenames differ from in-game names (Elixir Scramble = `desert_*`).
- In Lua, `GetTranslation(key)` is `CS.XLocalizationManager.instance:GetValue(key)` (no Lua-side table to scan); reflection on it from the reader is awkward, so use the bundle.
- Event rules/help pages are NOT in the client bundle (fetched from the server when the page opens): when guides and bundle are silent, say the rule is unconfirmed and give the best evidence (e.g. which result fields or history counters exist) instead of a guess presented as fact.
- Gift codes: no list exists on the client (redeem sends the typed code; the server checks it). Current codes come from fan sites (lastasylum.com/gift-codes is updated most often; others disagree on what expired). The redeem errors form an existence oracle: 90015 not found, 90022 expired, 90021 not valid yet (= exists, not released), 90011 wrong kingdom, 90017/90006/90010 already used, 90018/90009 limits. Testing guesses means real redeem requests (a valid code is claimed on Aegis) and bulk guessing is ToS-grey enumeration: describe it and ask the owner before sending any.

## Chat text filtering (client only)
- Send-side checks live in `Ability.Tools.Utils.GStringUtil`: `CheckRichStringForSend` (upvalue `strList`: 52 tag openings like `<size=` `<color=` `<b>` `<font=` `<link=` `<#`, plus `[`-bracket twins), `HasRichTextTag` (upvalue `richTagNameSet`: 34 TextMeshPro tag names, case-sensitive), `HasColorCode` (4 hex patterns); the input box also refuses `<` as an invalid character. It is a blocklist, not an allowlist: `<sprite>`, `<gradient>`, `<br>` and uppercase tags are not in it, and `<u> <sup> <sub> <nobr> <noparse> <rotate> <pos> <page>` are detected but not in the send list.
- Display is inconsistent: the chat-list preview and the main-screen ticker render rich text, the open chat bubble and rally invite card show tags literally, line breaks collapse to spaces. Read lists with `debug.getupvalue` and call only the pure `Has...` checks; `Check...ForSend` may show a UI toast.
- Group invites: DM message `messageDetail.groupInviteMessageDto{chatRoomName, chatRoomDto.roomIdentId.groupCommonIdent.chatGroupId}`; join = `chat.ChatGroupConfirmC2S{agree=true, groupRoomInfo=chatRoomDto, messageId, roomInfo=<DM roomInfo>}` (a scripted call without the full UI payload got 22201).
- Sending a group invite: `chat.ChatGroupInviteC2S{roomInfo = room:GetChatRoomDto(), memberId = {playerId}}`. memberId is a REPEATED int64: a scalar makes pb.encode throw, the error is swallowed below the send hook, nothing goes out and no reply comes (looked like a silent server ignore). Found by decoding the game's `UIChatGroupPanel` (AddMember mode) from `luascript_logic.assetbundles`. The server sends no ack either way; an invite to an existing member is ignored. Full member list: `chatRoomInformation.chatGroupInformation.serverMember[sid].memberId` (room.memberIds holds only locally loaded members).
- Reading lazily loaded UI scripts offline: pull `ABAsset/*/luascript_*.assetbundles` (98 bundles), UnityPy TextAssets, bytes xor `eyugame_lua_zombiesrpg` -> Lua 5.4 bytecode (`\x1bLuaT`); grep the printable string constants around a request name to see the call shape. pb.fields(t) yields (name, number, type, default, label); pb.encode with a wrong scalar/list shape is the quick check.
- Sender's home kingdom: chat message objects carry `senderInfo` (ChatPlayerDto: serverId, playerId, name...) on `room.m_Messages[*]`; works when the player is away on KvK (the map does not).
